# School Management System – Fixes

Date: 2026-10-08

## Fixed

### 1. Homework portal/display errors
- Reworked the parent/student homework query to be compatible with MySQL `ONLY_FULL_GROUP_BY`.
- Removed the invalid `GROUP BY homework.id` pattern.
- The latest homework evaluation and latest student submission are now selected safely.
- Enrollment matching now includes `branch_id` to prevent cross-branch matches.
- Parent/student homework pages gracefully render an empty list when there is no enrollment in the active academic session.

### 2. Exam schedule not displaying
- Reworked the parent/student exam schedule query so it returns one row per exam without selecting `timetable_exam.*` while grouping only by `exam_id`.
- Reworked the admin exam timetable list for the same MySQL compatibility issue.
- Exam timetable creation/update now scopes the existing-record lookup by branch.
- Exam timetable subject assignment now joins timetable rows within the same branch.
- Student/parent schedule detail remains restricted to the active child's class/section/branch.

### 3. Branch creation
- Fixed branch inserts for strict MySQL schemas where legacy branch columns are `NOT NULL` without defaults.
- Safe defaults are now supplied for registration, password-prefix, timezone, payment, teacher restriction, and other legacy branch settings.
- Existing branch edit behavior remains compatible.

### 4. Additional related SQL compatibility fixes
- Fixed the home exam-list query to use `DISTINCT` instead of an invalid `GROUP BY`.
- Fixed the marksheet student selection to use `DISTINCT` instead of grouping by only student ID.

## Term/Semester compatibility

The existing academic-term/semester system remains intact:
- `gradebook_term` continues to define academic grading periods.
- `exam.grading_term_id` remains supported.
- The older `exam.term_id` / `exam_term` relationship remains supported.
- Homework remains session-scoped because its existing database table has no `term_id`; the fix does not silently introduce a new homework term requirement.

Replace the existing application with this package after making a backup.

No SQL migration is required for the fixes in this package.


## Follow-up: weighted exams in term gradebook

- Exam create/edit now includes a `Gradebook Weight (%)` field and keeps the academic term/semester selection.
- Scheduled exam components automatically use that percentage in the matching term's gradebook. Example: an exam weighted at 20% contributes at most 20 points, leaving 80% for other components.
- Student exam scores are proportionally converted from the exam's original full-mark scale to the configured gradebook weight. Example: 40/50 becomes 16/20.
- Existing exams with no saved weight retain the previous raw-full-mark behavior until edited.
- Before deploying this follow-up to an existing database, back up the database and run `database/exam_gradebook_weight_upgrade.sql` once.
